# ACM Helper · C++ 算法可视化

让算法初学者「看见」程序在做什么。

写一段真实的 C++ 算法代码，像在 CLion 里一样打断点、单步执行；每走一步，数组、二维数组、结构体里的数值就在原位置更新并变绿，邻接矩阵、边表、父节点数组还能直接画成图或树，标出访问状态、当前节点和最短距离。不用在脑子里模拟循环和递归，变化就摆在眼前。

程序由本机真实的 GCC / GDB 编译和调试，看到的每一个值都来自程序真正运行时的内存，而不是预先做好的动画。

## 能看到什么

| 数据 | 可视化方式 |
| --- | --- |
| 普通变量 | 顶部数值标签，改变时变绿 |
| 指针 | 显示指向的位置和值，如 `p → main 的 a[21] = -1`，不再只是一串地址 |
| 一维数组 / `vector` | 带下标的格子，修改的格子变绿并闪烁一次 |
| 二维数组 | 矩阵表格，适合观察 DP 表、Floyd 距离矩阵 |
| 结构体 | 按字段展开 |
| 邻接矩阵 / 边表 / 父节点数组 | 通过「结构绑定」画成图、树或森林，青色 = 已访问，金色 = 当前节点 / 边，绿色 = 数值改变 |
| 递归 | 底部调用栈，点击可切换到任意一层查看当时的变量 |
| 大数组 | 自动分页、折叠相同值区间，可用 `a[100]`、`a[90..110]` 固定查看重点 |

编辑器中蓝色行是下一步将要执行的代码，淡金色是上一次暂停的位置。变化过的数值会一直保持绿色，直到重新运行或点击「重置变化标记」；只有一步之内批量写入大量相同值的操作（如 `memset`、`fill`、`assign`）才会被归为「疑似初始化」而不标绿，可在可视化区域上方关闭「初始化推断」；单步执行中逐个写入的元素始终标绿。

## 启动

Windows 双击 `start.cmd`，浏览器打开 **http://127.0.0.1:4173**。使用期间保持启动窗口打开，关闭窗口即停止服务。`start.cmd` 会在首次启动或界面代码有更新时自动构建；如果之前启动的窗口还没关，会自动关闭旧的服务再启动新版本。

首次使用需要安装 Node.js 22+，以及带 Python 支持的 MinGW GCC 与 GDB（已在 GCC 16.1.0 / GDB 17.2 上验证）。也可以手动执行：

```powershell
npm ci
npm run build
npm start
```

开发模式使用 `npm run dev`。端口默认 4173，可用 `PORT` 环境变量修改。编译器和调试器默认取 PATH 中的 `g++`、`gdb`，可在右上角「设置」中填写绝对路径，或使用 `CXX` / `GDB` 环境变量。

## 上手

1. 点击左上角项目名，选择「打开文件夹…」，在弹出的资源管理器窗口里选择 `example` 下的任意示例（如 `dijkstra`）；或选择「新建项目」从空白开始。
2. 点击行号左侧设置断点，按 Shift+F9 开始调试：程序会直接运行到第一个断点停下；一个断点都没设时，停在 main 的第一句。
3. 按 F8 一行一行执行，F7 进入函数（观察递归），F9 运行到下一个断点。和 CLion 一样，F7 只进入你自己写的函数，不会钻进 `max`、`swap`、`sort` 等标准库内部；进入的函数在其他文件（如头文件）里时，编辑器会自动切换过去。也可以点「自动单步」，按设定速度像动画一样连续播放（0.1—100 步/秒）。也可以点「自动单步」按设定速度连续播放（0.1—100 步/秒），旁边会显示实际达到的速度；速度超过单步本身的极限时会一次连走多步、只刷新最后一步的画面，绿色变化标记不会丢。
4. 右下方「可视化」区域实时显示变量；需要把数组画成图时，点「结构绑定」说明哪个变量是矩阵 / 边表 / 父节点数组。
5. 程序需要输入时，点击左下终端直接输入并回车。

各示例要观察的变量和预期结果见 [示例说明](example/README.md)。

## 界面与项目管理

界面配色参考 CLion，提供深色与浅色两套主题，可在「设置 → 外观」中选择深色、浅色或跟随系统，也可以点右上角的太阳 / 月亮图标快速切换。编辑器、终端和图视图会同步换色。

左侧项目区的操作方式与 CLion 相近：

- 点「新建源文件」或按 Alt+Insert，在文件树中直接输入文件名；不写扩展名时默认为 `.cpp`，新的 `.cpp` 文件自带 `main` 函数模板。
- 双击文件名或按 F2 重命名，按 Delete 删除；在 Windows 上删除的文件会进入回收站，可以还原。
- 右键文件可以「设为编译入口」：一个项目里可以放多道题的 `.cpp`，切换入口即可分别运行和调试。
- 「打开文件夹…」调用 Windows 资源管理器选择文件夹，不需要手动输入路径；右键菜单中的「在资源管理器中显示」可以快速找到文件。

程序运行或调试时，为避免源文件与正在调试的程序不一致，重命名和删除会暂时禁用。四个分区之间的分界线可以拖动，布局保存在本机浏览器中。

## 图与树的结构绑定

「结构绑定」只描述数据的含义，与具体算法无关，同一份配置可以用于 BFS、Dijkstra、Prim 等不同算法。配置保存在项目文件夹的 `.cppide.json` 中，不会改动源代码。

| 来源 | 需要填写 | 举例 |
| --- | --- | --- |
| 邻接矩阵 | 二维数组、节点数、节点下标起点、无边标记 | `G`、`n`、`0`、`INF` |
| 边表数组 | 起点数组、终点数组、边数、节点数；权重可空 | `from`、`to`、`m`、`n`、`weight` |
| 父节点数组 | 父节点数组、节点数、无父节点标记 | `parent`、`n`、`-1` |

还可以绑定 `visited` 这样的状态数组、`dist` 这样的数值数组，以及表示当前节点和当前边的变量（如 `u`、`v`），并限制它们只在某段代码行内高亮。`INF` 要显示为 `∞` 时需填写对应的值。

几点说明：边表从数组下标 0 开始读取，节点编号可以从 0 或 1 开始；零权边只有在无边标记不是 0 时才会显示；无向矩阵的重复边会自动去重，自环与平行边会让树布局退回普通图布局。边权默认隐藏，鼠标悬停在某条边上时才显示，避免标签互相遮挡。节点位置可以拖动并保存。单个视图最多 200 个节点、500 条边，超出时会提示原因，不会画出错误的图。

## 大数组

一维数组 / `vector` 达到 32 个元素时，连续 16 个以上相同值的区间会折叠成一格，并标明范围和原因；已变绿的元素不会被折叠。超过 200 个元素的数组还会分页显示。按网格显示的二维数组不折叠，以免行列错位。可以输入 `a[100]` 或 `a[90..110]` 固定查看，也可以按下标定位、前后翻页。

折叠只影响显示，不影响监测。完整监测的基础类型数据总量默认上限 8 MiB；超出时请在「监测范围」中为大数组指定区间。「初始化推断」只把单步内批量写入相同值（至少 16 个元素）的操作识别为初始化，可以随时关闭。

## 实现概览

`src/` 是 React + Monaco + Cytoscape + xterm.js 前端；`server/` 是 Node 本地服务，负责 GDB/MI 调度、GDB Python 采集器、Windows 原生终端和系统对话框；`shared/` 是前后端共用的消息类型与图结构处理；`example/` 是可直接打开的示例项目。

编译时把项目复制到临时目录，使用 `-std=c++17 -g -O0 -fno-omit-frame-pointer -fno-inline`，并加入函数退出钩子，在 `main` 正常返回前采集最终快照，保证最后一步的变化也能看到；用户源文件不会被修改。C++ 整数以字符串传输，避免 64 位整数在 JavaScript 中丢失精度。数组在采集器中按块比较，只把可见窗口、折叠摘要和变化元素发给前端。

本地服务只监听 127.0.0.1，并校验 Host、Origin 与随机会话令牌。它运行的是用户自己的代码，没有面向不可信代码的沙箱，请不要部署到公网。

## 当前限制

每次编译一个 `.cpp` 入口文件加项目内头文件，仅支持单线程程序。数值数组、二维数组、普通结构体和 libstdc++ 数值 `vector` 有专门展示，`vector<bool>` 等特殊布局暂不支持。单步展示的是两次暂停之间的结果：同一行内的多次修改会合并显示，「继续」不会补放中间过程，也不支持反向执行。
